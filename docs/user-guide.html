01 / GET RUNNING

A single app for research and paper decisions

MacroTrading v0.5 combines the two earlier prototypes into one local application. The browser, research reports and portfolio controls use the same Python engine and SQLite state.

1. Start

Run the local Python server and open the dashboard.

2. Review

Accept sourced evidence, inspect scores and record decisions.

3. Assess

Check portfolio impact, then stage and execute a paper order separately.

Install and launch

Use Python 3.11 or newer, Git, and a modern browser. Clone the implementation branch below. Alternatively, extract the accompanying implementation ZIP and run python3 run.py inside its folder. No third-party Python package is required when your operating system supplies IANA timezone data.

git clone --branch codex/integrated-research-workbench https://github.com/AInewbie/MacroTrading.git
cd MacroTrading
python3 run.py

Open http://127.0.0.1:4173. Keep the terminal running while using the application. Stop with Ctrl + C.

On Windows, use py -3 run.py. If the system has no IANA timezone database, install tzdata into the Python environment first. The optional compatibility command node server.mjs launches the same Python application; it does not run a second engine.

python3 run.py --port 4174 --data-dir ./var-second

The second command creates an isolated workspace with its own database. Use it for experiments or to load the dated example after your main workspace has advanced to a later review date.

What this release is: a local, single-user research and paper portfolio workbench. It does not contain live brokerage execution or a scheduler. Starting it does not contact market sources or an AI provider.
Publication status: the enhanced implementation is published on codex/integrated-research-workbench. It is available for review in a pull request and has not been merged into main. Open pull request #7 ↗.

02 / FIRST TEN MINUTES

A practical first-run walkthrough

  1. Load the example. On Overview, choose Load historical example before running a current-dated review. This commits the repository's September 16 research input and creates a saved report.
  2. Read the labels. The portfolio uses synthetic marks and holdings. The dated research fixture contains repository-supplied claims and prices that have not been independently verified. It demonstrates software behavior.
  3. Inspect a theme. Open Research themes. Compare WATCH, evidence freshness, market coverage and lifecycle. Expand evidence, counterdrivers, tests and catalysts.
  4. Try a decision. Choose Record decision, select Suspend, and enter a reason. The theme stays suspended on later runs. Use Resume after review only when the reason has been resolved; an active market invalidation can still suspend it.
  5. Inspect risk. Open Portfolio risk. Review DV01, vega, scenario losses and manual factor overlap. Enter an instrument, side and quantity to assess a proposal.
  6. Try paper accounting. In Paper orders, stage a small order, inspect the checks, then choose Paper execute. Check that cash and holdings change together. A limit outside the simulated price remains unfilled.
  7. Open the saved report. Run archive retains the input/result JSON and full HTML from each committed run. The report's portfolio snapshot is frozen at that run's time.
  8. Move to your own data. Import or edit holdings, cash, marks, FX, liquidity and derivative economics. In Settings, turn off Synthetic demo input mode. Resolve any data issues before paper execution.

04 / RESEARCH MODEL

Scores, evidence and lifecycle are separate

The five inherited themes

ThemeTreatment in v0.5
Oil, refined-fuel scarcity and inflationPreserved as unscored research until an explicit reproducible component baseline is defined.
AI capex repricingWATCH-scored thesis with sourced events, counterdrivers and a configured market proxy.
Japan normalizationWATCH-scored thesis with a configured proxy and two-session market confirmation.
China domestic demandWATCH-scored thesis with its own evidence, tests and market proxy.
European defenseWATCH-scored thesis; automatic market confirmation remains unavailable until a matching listing/calendar is configured.

These are inherited research definitions, not fresh investment conclusions. Edit them when assumptions, catalysts or evidence change.

WATCH arithmetic

WATCH = clamp(25P + 25F + 20M + 20C + 10X − 10R, 0, 100)
ComponentMeaningAccepted values
PPrimary-source support0, 0.5, 1
FPredeclared fundamental tests0, 0.5, 1
MMarket confirmation0, 0.5, 1
CCatalyst proximity0, 0.5, 1
XExpression quality0, 0.5, 1
RIndependent counterdrivers0, 1, 2

Default score bands are below 45: Exploratory watch, 45 to below 70: Research review, and 70 or higher: Priority research. The weights are editable in Settings; positive weights must sum to 100 and the R weight must be zero or negative. A weight change records a reason and re-evaluates accepted evidence.

WATCH is a prioritisation rubric. It is not a probability, expected return, calibrated confidence or instruction to trade.

Evidence quality and coverage

Coverage is missing, current or stale, based on accepted evidence and the theme's configured age limit. Evidence quality is a transparent heuristic: 60% source-group breadth, capped at two groups, plus 40% freshness with a 21-day half-life. It does not verify publisher independence or establish truth. Analyst decisions without external sources can refresh the accepted-event clock, but do not add source breadth.

Persistent lifecycle

Action/stateMeaning
ReviewRecord reasoning and optional accepted score updates. Does not activate a position.
DeferRecord that a decision is deferred; does not automatically suspend the theme.
Suspend / SuspendedPause the theme while a condition is unresolved. Persists across repeated runs.
Invalidate / InvalidatedRecord that the thesis has failed. Overrides even a high WATCH score.
Resume after reviewExplicitly reopens a theme; current market invalidation still takes precedence.
Archive / ArchivedRetains the history and marks the theme inactive until an explicit reviewed transition.

Material evidence, meaningful score changes, lifecycle transitions and confirmed market breaches create deduplicated alerts. A market-only change can now create a score alert. A run with no alert does not imply that missing data are reassuring.

05 / INPUT WORKFLOW

Add, correct and review evidence

Manual entry

  1. Open Research themes → Add evidence.
  2. Select the theme, classification and direction: support, contradict or neutral.
  3. Write the reviewed claim and record its observation time. Facts, plans, forecasts and market-implied claims require a direct source URL, title and publication time. Analyst inference can be source-free but is labelled as inference.
  4. Mark it material only when it warrants a change alert. Add component updates only when justified; blank fields retain accepted values.
  5. Choose Accept evidence & run review. The accepted ledger, score, run report and action history are committed together.

Available classifications: observed fact, company plan, policy plan, economist forecast, market-implied pricing and inference. A plan must not be relabelled as an achieved outcome.

Structured research imports

Choose Import research JSON, inspect the input in the review dialog and then save. The file contains as_of, optional label, evidence and market_closes.

{
  "as_of": "2026-09-18T21:00:00Z",
  "label": "Example analyst review",
  "evidence": [
    {
      "id": "manual-unique-001",
      "theme_id": "japan_normalization",
      "observed_at": "2026-09-18T10:00:00Z",
      "first_known_at": "2026-09-18T12:00:00Z",
      "kind": "inference",
      "direction": "neutral",
      "material": false,
      "summary": "Illustrative analyst inference, not a market observation.",
      "sources": [],
      "component_updates": {}
    }
  ],
  "market_closes": []
}

Corrections and point-in-time rules

Reusing an ID with identical content is harmless. Reusing it with changed content is rejected. Correct an event with a new ID and supersedes: "old-event-id" in a structured import; the older event remains visible as superseded.

Publication, retrieval, observation and first-known times are retained separately. Information dated after the run cutoff is rejected. The current ledger cannot be rewound: use Evaluation or a separate workspace for historical replay. The fixture's information is not independently verified merely because it passes these structural checks.

06 / SOURCE ACQUISITION

Refresh approved publishers, then accept claims

Source retrieval is explicit. Nothing polls in the background or changes scores when a headline arrives.

Bundled connectorWhat is retrievedWhat you must do

  1. Open Sources & evidence → Refresh enabled sources.
  2. Read Source health. Failures are visible and do not silently substitute demonstration data.
  3. Open each pending item's original publication. The inbox stores the retrieval time and raw-response hash.
  4. Choose Review & accept, edit the summary/classification and add justified component updates. Dismiss irrelevant items.

Add a feed or market CSV endpoint

Configure sources opens the validated JSON configuration. Supported kinds are rss (RSS/Atom), ecb_fx and market_csv. Retrieval requires HTTPS, approved exact hostnames, public DNS resolution and bounded response size. Add permitted redirect hosts explicitly. Do not put API keys or other credentials into source URLs; authenticated vendor adapters are not included.

[
  {
    "id": "publisher-example",
    "name": "Illustrative approved feed",
    "kind": "rss",
    "url": "https://example.com/feed.xml",
    "allowed_hosts": [
      "example.com"
    ],
    "enabled": false,
    "source_group": "publisher-example",
    "theme_ids": [
      "japan_normalization"
    ]
  }
]

The example URL is a placeholder. Configure a real publisher and verify its terms and content. RSS content is stored as source material, never as instructions to the application.

Each refresh handles at most 100 feed entries per source, uses up to three concurrent fetches, a 10-second request timeout and a 2 MB source-body limit. Duplicate candidate IDs are not re-added. Failed sources can be retried manually; scheduling, automatic retry policies and licensed comprehensive data coverage are future work.

Official directories: Federal Reserve feeds · ECB feeds · ECB reference FX.

Use completed, aligned trading sessions

Import market CSV in Sources & evidence, or include market_closes in a research JSON input. Review the parsed observations before committing them.

theme_id,session_date,proxy_close,benchmark_close,proxy_return_pct,benchmark_return_pct,completed,source_url,close_at,benchmark_close_at,convention,currency,benchmark_currency

This CSV row is synthetic. Prices, anchors and benchmarks must describe your actual configured proxy. Return fields use percentage points: 1.25 means +1.25%.

CheckBehavior
Distinct adjacent sessionsTwo copies of the same session count once. Weekends and configured holidays are skipped when testing adjacency.
Calendar and close timeThe venue/year must be explicitly configured and the timestamp must match its close, including early closes.
Matching benchmarkRequired benchmark prices, timestamps and currencies must align. Cross-currency or asynchronous comparisons do not confirm.

The bundled XNYS calendar covers 2026 only, with US cash-market holidays and early closes, based on NYSE hours and calendars. Unknown years and the unconfigured European listing cannot produce verified confirmation. Add a reviewed calendar in Settings → Advanced configuration before using another venue/year.

Full M requires two adjacent sessions meeting the configured directional daily threshold. Ordinary anchor breaches also require two adjacent sessions on the same side. Market invalidation is automatic only where an explicit numerical invalidation threshold is configured; narrative invalidation still requires analyst review.

08 / PORTFOLIO SETUP

Make units and assumptions explicit

Portfolio shows NAV, cash, unrealized and realized P&L, positions and the instrument universe. Add position and Edit change starting holdings directly. These manual edits are audited but do not fabricate a cash transaction; use Paper orders for simulated trading and accounting.

Starting your own portfolio

  1. Export a backup of the demonstration workspace if you want to retain it.
  2. Import a v3 workspace or add/edit instruments, positions, cash balances and FX rates.
  3. Set marks and their timestamps, currencies, multipliers, lot/tick sizes, liquidity and financing assumptions.
  4. Supply derivative sensitivities and margin parameters where relevant.
  5. Turn off Synthetic demo input mode in Settings and resolve the displayed issues.
Instrument modelValuation / unitsRequired extra economics
Equity / ETFQuantity × mark × multiplier. Normally multiplier = 1.Current mark, instrument-unit ADV, optional beta and factor loadings.
BondDirty price per 100 × quantity × multiplier. Multiplier = face value per contract / 100.Explicit DV01 per contract per bp, or duration for an approximation.
FXFunded spot-unit asset in its quote currency. Not an FX-forward/swap model.Correct quote currency, multiplier and FX path to the reporting currency.
OptionPremium × quantity × multiplier; directional risk uses underlying × delta.Call/Put, expiry, strike, underlying price, delta, gamma, vega; margin rate for shorts.
FutureNAV contribution is unrealized P&L. Full contract notional is tracked as exposure.Contract multiplier, explicit equity/commodity/FX risk factor and margin rate.

The demonstration TLT holding is a simplified duration-based rates proxy; replace it with the appropriate instrument model for your actual holding. Other demo contracts and marks are illustrative, not contract-master records.

Cash, FX and cost basis

Edit cash & FX accepts currency balances and dated conversion edges. A rate from EUR to USD of 1.10 means 1 EUR = 1.10 USD. Reporting can invert or chain usable rates; missing conversion makes affected totals unavailable. Conversion for reporting does not exchange cash: a foreign-currency purchase needs cash in that currency.

The engine uses average cost. Adding in the same direction recalculates average entry. A partial close preserves the remaining entry price. A reversal realizes the closed portion and resets the new position's entry. Fees reduce cash and realized P&L. Futures use open-trade unrealized value plus realized cash when closed; daily exchange variation-margin settlement is not modelled.

A target weight is a signed fraction of NAV in delta exposure, not premium market value. Zero-quantity rows can retain a target and participate in a rebalance preview.

Read-only broker reconciliation

Choose Import broker snapshot to compare a broker-neutral JSON file with model holdings. It reports quantity breaks, unmapped instruments and cash comparability, with account IDs masked. No holdings are overwritten.

09 / RISK AND IMPLEMENTATION

Inspect the portfolio before staging a quantity

What the risk panel measures

MeasureInterpretation
Gross / net delta exposureAbsolute and signed directional exposure in the reporting currency. Not a probability-weighted loss measure.
DV01Approximate currency loss for a +1 bp parallel yield move, with sign determined by the holding.
VegaCurrency P&L per one volatility percentage point. Input is per contract and is not multiplied again by the option contract multiplier.
Gamma P&LSecond-order option P&L for a 1% underlying move, using supplied gamma.
Estimated marginConfigured futures and short-option rates. It is not a broker margin calculation.
Factor overlapDollar delta × manually supplied factor loadings, grouped by theme. No covariance or correlations are inferred.

Four explicit stress cases

ScenarioEquityRatesFXCommodityVolatility
Global risk-off−12%−100 bp−4%−8%+10 points
Inflation resurgence−7%+125 bp+2%+16%+6 points
Broad USD decline+4%−25 bp+9%+10%+2 points
Rates +100 bp0%+100 bp0%0%0 points

These are illustrative supplied shocks, not forecasts. Bonds use DV01; options use delta/gamma/vega; other models use linear price shocks. The scenarios do not fully reprice options, currency cash balances, correlation changes or nonlinear rates exposures.

Assess a proposed expression

  1. Choose the instrument, optional research theme, Buy/Sell, quantity, scenario risk budget and holding days.
  2. Select Calculate portfolio impact.
  3. Compare before/after scenario P&L, the largest adverse incremental scenario change, estimated round-trip costs and all pre-trade checks.
  4. When eligible, explicitly choose Stage this paper proposal, then review and execute it separately in Paper orders.

Theme-linked proposals require an accepted active theme with current evidence; a configured market proxy also needs current market coverage. The quantity is supplied by you. There is no optimizer, inferred target weight or automatic recommendation. Direct manual trade tickets are independent portfolio actions; their theme tag does not replace your thesis review.

Estimated costs use configured commission/slippage and annual carry/borrow over the selected holding period. Options use premium rather than underlying notional for this cost estimate. These remain assumption-based approximations, not executable quotes or a financing contract.

10 / PAPER EXECUTION

Stage, inspect, execute and verify

  1. Open Paper orders → New paper order.
  2. Select instrument, side, quantity and Market or Limit. For a limit, supply a valid tick-size multiple. Quantity must respect the instrument's lot size.
  3. Select Stage and check. Read the results. Staging alone does not alter positions.
  4. Choose Paper execute. The engine rechecks the current portfolio, marks and constraints.
  5. Inspect the resulting status and fill ledger; return to Portfolio to verify cash, quantity and cost basis.
StatusMeaning / next step
StagedRecorded and passed staging checks. It can still fail later if inputs or holdings change.
BlockedAt least one control failed. Fix the cause and create a fresh reviewed order.
UnfilledThe simulated market price, including slippage, is outside the limit. Update marks and retry or cancel.
FilledA fill, cash movement and holding update were committed together. Repeated execution returns the existing fill.
ImportedImported unfilled orders are inert. Create a fresh order before execution.
CancelledThe order is retained for history and cannot execute.

Implemented controls

Checks include tradability, known FX/notional, order size, option/futures contract counts, required option limits, complete economics, gross/net exposure, currency cash availability, estimated margin, shorting policy, ADV participation and portfolio scenario loss. Missing economics are not silently replaced with zero risk.

Paper fills use the current mark plus/minus configured slippage. There is no queue simulation, partial-fill model, market depth or broker acknowledgement. A buy limit at 100 with a simulated fill at 100.02 remains unfilled. Stop orders are explicitly unsupported.

Rebalance preview

Set target weights on position rows, then choose Preview target rebalance. Review each rounded quantity and limit before staging. A zero-position target is supported. The preview does not solve for transaction costs, correlated risk, turnover minimization or an optimal portfolio.

11 / OPTIONAL AI

Source-cited proposals that require review

Manual research works without an AI account. To enable extraction, set OPENAI_API_KEY and OPENAI_MODEL in the server's environment and restart. Select a model available to your account that supports Responses API structured output. No model is chosen automatically; .env files are not loaded automatically.

  1. Refresh source feeds and select 1–10 pending candidates.
  2. Choose Propose claims with AI. This sends selected titles/summaries, timestamps, candidate IDs and theme definitions to OpenAI.
  3. Inspect the suggested theme, classification, direction, candidate citations and uncertainty.
  4. Independently review the original source. Accept evidence manually through its source card; copy a proposed summary only after checking it.

The key stays on the server and is excluded from exports. Output uses a strict schema; unknown theme labels/citation IDs, refusals and incomplete responses are rejected. The recorded result includes model, prompt version, request hash and token usage.

Explicit limits: five requested attempts per UTC day, ten candidates per request and 2,000 maximum output tokens. Failed requests count toward the daily limit. These controls are not a guaranteed monetary spending cap; provider billing applies. No paid AI request was made during implementation testing.

AI cannot accept its own claims, edit score components, generate order quantities or execute trades. Prompt/schema guidance follows the official OpenAI structured-output documentation.

12 / EVALUATION

Test chronology and assumptions separately

Research replay

Choose Research event replay in Evaluation and supply chronological batches. Each batch has as_of, optional evidence/market observations and optional expected_alerts. The replay starts from a fresh state and cannot mutate your active research ledger.

{
  "batches": [
    {
      "as_of": "2026-09-16T21:00:00Z",
      "evidence": [],
      "market_closes": [],
      "expected_alerts": []
    },
    {
      "as_of": "2026-09-17T21:00:00Z",
      "evidence": [],
      "market_closes": [],
      "expected_alerts": []
    }
  ]
}

Expected alerts use strings such as material_evidence:japan_normalization. Labelled runs report true/false positives, missed alerts, precision and recall; no calibration metric is invented for unlabelled data. The replay uses the currently supplied configuration, so historical configuration/anchor changes must be reconstructed explicitly.

Single-expression paper backtest

The default Evaluation form contains synthetic prices and timestamped target exposures. Replace them with a reviewed dataset. Targets range from −1 to +1; signals execute at the following observed close and only earn returns after that execution point.

{
  "prices": [
    {
      "at": "2026-09-14T20:00:00Z",
      "close": 100
    },
    {
      "at": "2026-09-15T20:00:00Z",
      "close": 102
    },
    {
      "at": "2026-09-16T20:00:00Z",
      "close": 101
    }
  ],
  "signals": [
    {
      "known_at": "2026-09-14T20:00:00Z",
      "target": 1
    }
  ],
  "transaction_bps": 5,
  "borrow_bps": 200,
  "financing_bps": 300
}

Outputs include the interval ledger, modeled net return, maximum drawdown, turnover, terminal liquidation cost and volatility. Carry accrues over elapsed days; volatility annualization assumes daily trading observations. This diagnostic does not infer a trading calendar, dividends, corporate actions, selection bias or realistic derivative settlement. It does not validate profitability of the five macro themes.

13 / REPORTS AND RECOVERY

Keep decisions reproducible

Every committed run produces a report

Open Overview → Open full HTML report, or select any run in Run archive. The report contains all themes, accepted evidence and contradictions, lifecycle, coverage, scores, tests, catalysts, portfolio snapshot, scenarios and a reproduction manifest.

The manifest records application/code, configuration, input, previous/next research state and portfolio hashes. Download the run JSON to inspect the exact inputs and the result. Code must still be checked out at the matching version to reproduce its behavior.

Later portfolio edits do not rewrite old reports. Run a new review to capture updated holdings in a new report. The action hash chain helps detect accidental modification, but is not an independent tamper-proof record against someone controlling the local database.

Default data location: var/macrotrading.sqlite3. For a complete backup, stop the server and copy the entire var directory, including any SQLite sidecar files. Settings → Restore state backup presents the incoming JSON for review before replacement. Existing archive entries in the destination database remain; the pending source inbox is cleared.

Legacy migration

Original browser v1/v2 workspace exports are accepted through Import workspace. Their original orders/audit are retained as legacy_history, and old fills are never replayed. Add mark timestamps, FX, liquidity, margin and financing assumptions, then reconcile cash and holdings. Futures-style valuation can change NAV relative to the old notional-based display.

Original Python v1 alert state is insufficient to reconstruct accepted component updates. It is rejected explicitly; rebuild from archived evidence/market inputs instead.

Standalone command-line reports

PYTHONPATH=src python3 -m macrotrading.cli \
  --config config/live_themes.json \
  --input examples/integrated_research_run.json \
  --full-review --html-out review.html --state-out state.json

Pass --state state.json for later chronological CLI runs and --json for machine-readable output. The CLI is separate from the web database: it does not silently update the dashboard or include its portfolio.

Repeat execution could apply twiceAlready-filled orders return the original fill.
Zero holdings were skipped by rebalancingUnit delta converts the target even from zero quantity.
Browser and Python logic were disconnectedThe browser and report renderer consume one authoritative backend state.
